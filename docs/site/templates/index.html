traj_compare · robot_msgs.compare

Compare any trajectory against a reference — target, sim or real.

Get the error signal, the standard numbers, a verdict, an offline HTML viewer and an Open in Rerun backdoor.

robot_msgs.compare does the maths (pure numpy, one pair at a time). traj_compare draws it: one self-contained report.html plus one .rrd per comparison.

Three things, one source of truth

Every number the viewer shows comes from the library. The report and the .rrd read the same payload, so they cannot disagree.

Compare

The error, as a trajectory

compare(reference, measured) returns the error as the same type as its inputs, reference − measured (the ROS 2 sign), on the measured run's own samples.

  • Standard numbers per joint, axis and channel: rms, max, p95, final, IAE…
  • Never extrapolates: coverage and dropped travel with the numbers.
  • Cartesian: lag (+ = behind), cross-track, exact contour.
Judge

A verdict in ROS 2 terms

check() returns SUCCESSFUL, PATH_TOLERANCE_VIOLATED or GOAL_TOLERANCE_VIOLATED, the first violation and the margins left.

  • ToleranceMonitor runs the same rule per controller tick, so online and offline agree.
  • aggregate() splits N runs into accuracy (bias) and repeatability (spread), ISO 9283.
  • estimate_time_offset() measures latency.
View

Offline report, Rerun backdoor

One report.html that opens from disk forever: plots, 3D with the robot posed, synced videos, verdicts. No server, no CDN.

  • Degrees by default, one click to rad; every section show/hide-able.
  • rerun=True writes the same data as a .rrd with its layout inside.
  • An Open in Rerun button on every page.

Target → sim, target → real, sim → real

Comparison is pairwise on purpose. Pick the reference; the other run is measured against it. Sim → real needs no target at all.

{{pairings_svg}}

Target→Sim

Is the controller good enough, in sim? Tune here first: it is cheap and repeatable.

Target→Real

Does the robot do what we commanded? The number a customer cares about, and the one a verdict gates.

Sim→Real

Is the sim a faithful twin? Small sim → real error means sim results transfer.

Open in Rerun

The HTML report is the offline view you keep. Rerun is the backdoor for digging: the same numbers, one .rrd per comparison, its layout (blueprint) embedded, written by rerun-sdk=={{sdk}}. A file must be opened by a viewer at least as new as the SDK that wrote it, so every button and command names that version.

1 · Button

Served: it launches

Serve the folder with python -m traj_compare.serve. The button POSTs /__rerun/open?rrd=… and the server starts the pinned native viewer on that file (only files inside the folder).

2 · Copy

From disk: it copies

Opened as file:// or from a plain static server, the same button copies uvx --from rerun-sdk=={{sdk}} rerun <file>. Paste it in a terminal.

3 · Download

Anywhere: the file

Download the .rrd and open it in any Rerun {{sdk}} or newer. Served pages also offer “Rerun in browser” (app.rerun.io fetches the file from your server).
